## Findings

1. **§3.4 Top10Pages disclosure unimplemented and unreachable as designed (spec drift — resolve at fold).**
   Top10Pages.jsx is untouched by the cycle. Its `/pages` fetch carries no `min_severity`, so
   `pages_hidden` is always 0 for it (§3.1: "0 whenever min_severity is unset"); the one-line
   disclosure the spec asks for can never fire from that data. The behaviour the spec endorsed
   (drop unscored pages from a "pages to fix" ranking) is unchanged and correct, and the summary
   view where it lives already discloses excluded rows job-wide from P5.2. §7 done-when omits
   Top10Pages and the test table has no row for it — but a §3 change section bullet with no
   implementation and no recorded rejection is drift. Implement-with-source, or amend §3.4/§5.

2. **Chip wording deviates from spec.** Spec §3.4 says "muted `+N not scored` chip"; the shipped
   chip renders just `+N` (grey), with "not scored at this info detail" only in the `title`
   tooltip and in the panel-level sentence above. Contextually readable; the P5.2 tiles render
   the full "+N not scored" text. Either widen the chip or accept the short form consciously.
   Non-blocking.

3. **Coverage regression, undocumented:** the rewritten ByPagePanel.test.jsx dropped the E5
   citability-column render test and the P8 dash-for-absent-grade test (old crawls). Both
   behaviours are unchanged in the component (`ByPagePanel.jsx:43` → CitabilityBadge) and no
   replacement coverage exists anywhere (no CitabilityBadge.test.jsx). Restore a minimal
   assertion or record the deliberate drop.

4. **Commit-message claim not backed:** fc492fb says observation 3 (SummaryPanel unused `React`
   import) was "recorded in TODO" — TODO.md has no such entry (nor do LEARNINGS.md). Add the
   note or the record does not exist.

5. **`_VALID_SEVERITIES` comment overclaims** (`crawl.py:75-79`): "Derived from the store's own
   rank table so the two cannot drift" — it is a hand-copied literal; the store's rank table is
   method-local and not importable. Drift fails loudly today (a new store severity would 422),
   but the P14 silent direction returns if a rank is ever removed while the guard keeps admitting
   it. A parity test (router set == store rank keys) or hoisting the rank table would make the
   claim true.

6. **Untested UI branch:** the panel sentence's `pages_hidden > 0` clause (", and N pages left
   out of this filtered list") has no vitest fixture with `pages_hidden > 0` — backend-pinned
   (4.1/4.2) but the frontend rendering of that clause is unpinned.
