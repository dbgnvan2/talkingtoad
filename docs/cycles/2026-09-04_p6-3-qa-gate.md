2. **Spec §6's final done-when clause is not literally met.** "No rate is written as 0.0 when its denominator was zero" — true for `ga4_engagement_rate_mo`, false for `gsc_ctr_mo`/`gsc_avg_position_mo` (bare floats, deferred). 3. **The read-merge × fold motivating scenario has no permanent test.** The suite pins the merge (single-page section absence) and the fold (unit arithmetic) separately, but nothing pins "stored partial base + later bundle whose pages fold" — the exact double-carry the restructure exists to prevent. The gate probe (Evidence row 5) passes on HEAD; recommend promoting it to a permanent test in test_performance_ingest.py so a future per-page merge regression goes red.
4. **`index_state` within a folding bundle is first-wins by bundle order.** `merged = recs[0].model_copy` and `index_state` is not a sum field, so two folding GSC pages with different index states keep only the first page's (old per-page code was any-present-wins via `or`). Marginal — index_state rarely differs across www/scheme variants — and the store COALESCE protects the cross-ingest case. Cosmetic.
5. **Exact-duplicate source URLs within one bundle now sum instead of last-wins** (two identical URLs are treated as two traffic slices), and `folded_urls` would list the URL twice. The old code's in-batch merge was last-wins. Presumes the producer dedupes pages[]; if a producer ever emits the same URL twice in one bundle, clicks double-count. Producer-contract question, not a defect in this change.
